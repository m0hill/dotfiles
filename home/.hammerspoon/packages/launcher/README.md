# Launcher

Minimal Hammerspoon command palette for the small Raycast subset I actually use:

- native AppKit launcher UI through `hs.ui`
- app launching with app icons
- `fd`-backed file search with file-type icons
- text and image clipboard history with source/time context and full previews

Enable it from the Hammerspoon menubar: **Automations → Launcher → Enable**.

Default hotkeys:

- `Cmd+Space` opens the full launcher: apps, files, and clipboard.
- `Cmd+Shift+V` opens clipboard history only.

Both can be changed from the Launcher hotkey menu. Pressing the same hotkey again closes the launcher (or its preview). Switching between the two modes preserves the original paste destination.

Select a clipboard item and press **Tab** for a scrollable full-text or image preview. **Escape** or **Tab** returns to your results with the query and selection preserved; **Enter** pastes the item. You can also select and copy text inside the preview.

The launcher uses the custom `hs.ui` AppKit module inside Hammerspoon.

Clipboard history is stored locally in `packages/launcher/clipboard.json`. Images are stored as PNG files in `clipboard.json.images/`, with private directory permissions. Both are ignored by git. Clearing history or evicting an entry cleans up its image file. With persistence disabled, images use a session-only temporary directory.

The launcher and preview share the custom `hs.ui` HUD shell, native translucency, corner radius, and shadow. Full previews use a transparent `hs.webview` layered over that shell at the same position; no fork rebuild is needed.

## Notes

- File search uses `fd` asynchronously (installed via the Brewfile) over common home folders/dev roots with ignore/exclude rules for consistent low-latency results.
- File results use cached file-type icons by extension, with path-based icons as a fallback for folders or extensionless files.
- Clipboard results use a path icon for copied file paths, a web location icon for URLs, and a text document icon for normal text.
- Matching apps always appear before files and clipboard entries, so `chrome` prefers Google Chrome over a file named `chrome`. App search includes aliases for common system app renames such as `settings`, `prefs`, and `preferences`.
- App directories are watched for installations, removals, and renames, with debounced indexing and a 60-second reconciliation for missed events or newly created directories. The index has no app-count cap.
- File results show their paths, clear immediately on query changes, and preserve keyboard selection when asynchronous results arrive. Closing the launcher or switching to clipboard history cancels pending file searches.
- The empty launcher ranks apps by persisted launch usage instead of alphabetical order; use **Reset App Usage** from the menu to clear it.
- Clipboard history retains up to 200 entries (text and images combined), with text up to 256 KiB per entry. Images have a 32 MiB per-image and 256 MiB total storage budget; oldest images are evicted when the budget is exceeded. Search covers the full history and source app names, displaying the best 30 matches. Override entry/text/display limits with `maxClipboardItems`, `maxClipboardChars` (bytes), and `maxClipResults` in launcher settings.
- New entries show their source app and copy time; older entries may have an unknown source. Source detection uses the clipboard's declared source when present, otherwise the frontmost app when the clipboard watcher fires.
- Clipboard capture ignores common password-manager bundle IDs and standard concealed/transient/autogenerated pasteboard markers. Restoring a history item does not recapture it.
- Image history only captures images actually copied to the clipboard. For native screenshots without Screenshot Copy, use `Ctrl+Cmd+Shift+4` (selection) or `Ctrl+Cmd+Shift+3` (full screen). Normal `Cmd+Shift+3/4` saves to disk and is not captured by clipboard history. Screenshot Copy remains unchanged.
