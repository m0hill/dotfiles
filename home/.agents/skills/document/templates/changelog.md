# Changelog entry

Read the existing changelog before writing. Match its heading levels, categories, date style, voice, and placement. Update the current unreleased section unless the user names a release.

Include only notable effects on users, operators, or integrators. Exclude internal refactors unless they change supported behavior or operational risk.

When no changelog exists, ask before creating one. Recommend Keep a Changelog categories:

- Added
- Changed
- Deprecated
- Removed
- Fixed
- Security

Use one concise bullet per notable change. Describe the outcome from the reader's perspective. Before editing, confirm that an equivalent entry is not already present.
