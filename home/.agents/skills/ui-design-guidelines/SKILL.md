# UI Design Guidelines

Treat UI guidance as contextual constraints, not universal recipes. Establish the interface's users, tasks, platform, content, and accessibility needs before applying a rule.

Read only the references relevant to the current work:

- [Visual hierarchy](references/visual-hierarchy.md)
- [Layout grids](references/layout-grids.md)

- [Color and semantic color](references/color-and-semantic-color.md)

- [Microinteractions](references/microinteractions.md)
- [Image overlays and text legibility](references/image-overlays-and-text-legibility.md)

Prefer applicable accessibility standards, platform conventions, and the product's established design system over generic aesthetic advice. Validate the result in context rather than assuming that following a numeric recipe makes it usable. Apply the standards to all new behavior and the full behavior being refactored. Contain incompatible legacy patterns at the nearest boundary instead of copying them forward.
